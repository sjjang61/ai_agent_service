# Drive (개인 산출물 가상 공간) 상세 스펙 · 진행 계획 · 리뷰

> 상태: **P0~P3 구현 완료 (10장 참고)**. 7장의 결정은 권고안대로 확정해 진행했다.
> 이 문서는 [serverless-functions.md](serverless-functions.md) 의 Q1("드라이브는 무엇인가")에 대한 답이다. Functions 의 zip 패키지 저장소가 Drive 를 쓴다.

## 1. 목적과 범위

사용자마다 **개인 가상 파일 공간(Drive)** 을 둔다. 루트(`/`) 아래에 폴더를 만들고 지우고, 파일을 올리고 내려받으며,
**에이전트가 만든 산출물을 Drive 에 저장**해 대화·sandbox 수명과 무관하게 오래 보관한다. 형태는 Google Drive 와 비슷한 단순한 탐색기다(첨부 화면 기준).

| 구분 | 내용 |
|---|---|
| 하는 것 | 폴더 생성/삭제/이름 변경/이동, 파일 업로드/다운로드/이름 변경/이동/삭제, 경로 복사, 다중 선택 작업, 휴지통, 용량 제한, 에이전트 산출물 저장·불러오기 |
| 안 하는 것 (이번 범위 밖) | 다른 사용자와의 공유·권한, 공개 링크(→ 후속), 파일 동시 편집, 실시간 동기화 클라이언트, 버전 이력(→ 후속), 전문 검색 |
| Google Drive 와 | **무관**하다(외부 서비스 연동 아님). 기존 Google Drive 커넥터는 그대로 별개 기능 |

## 2. 현재 구조 (조사 결과)와 그 의미

"산출물을 MinIO 에 저장하고 있다"는 인식과 실제 구현이 다르다. 실제로는 다음과 같다.

| 위치 | 무엇이 | 수명 |
|---|---|---|
| **sandbox 컨테이너 `/workspace`** | 에이전트가 만든 파일 대부분(코드, 보고서, 이미지 …). 채팅 "Artifacts" 패널이 `/api/sandbox/artifacts` 로 **컨테이너를 직접 읽어** 보여 준다 | 대화방 sandbox 는 5분 유휴 시 종료. **대화방을 삭제하면 컨테이너·백업이 함께 삭제**된다 |
| MinIO `MINIO_BUCKET`(비공개) | sandbox **백업 tar** (`{session}/workspace.tar.gz`, 최신 1개). 개별 파일이 아니라 통째 아카이브 | sandbox 와 같음 (복구용) |
| MinIO `MINIO_PUBLIC_BUCKET`(공개) | 이미지 생성 결과, `upload_to_minio`, `publish_file` 로 발행한 파일 | 공개 URL, 만료 설정 가능 |

**의미**: 사용자 파일을 개별 객체로 두고 목록·이동·삭제할 수 있는 비공개 저장소가 **아직 없다**. Drive 는 새로 만드는 계층이며,
"통합 관리"는 기존 저장 위치를 합치는 것이 아니라 **"Drive 로 복사/저장"하는 새 경로를 만드는 것**이다. 즉 sandbox 와 Drive 사이에는 사본 관계가 생긴다(5.2).

재사용: MinIO 클라이언트·인증 설정(`object_storage.py`, 단 **공개 버킷 전용**이라 비공개 함수를 새로 둔다), 파일 종류 분류(`artifact_service.classify`),
미리보기 UI(`ArtifactsPanel`), 이름 중복 처리(`_unique_name`), 업로드 한도 설정 패턴.

## 3. 상세 스펙

### 3.1 개념

- 사용자당 Drive 하나. 루트 폴더(이름 "Drive", 경로 `/`)는 삭제·이름 변경·이동 불가.
- 노드 = 폴더 또는 파일. 한 폴더 안에서 이름은 유일하다(**대소문자·악센트 구분 없이** — DB 기본 collation 과 일치, 5.2-6 참고).
- **경로**: `/보고서/2026/요약.pdf` 형식. 경로는 표시·복사용이고 **식별자는 id** 다(이름을 바꿔도 링크·참조가 깨지지 않는다).
- 이름 규칙: 1~255자, `/`·`\`·NUL·제어문자 불가, `.`·`..` 불가, 앞뒤 공백 제거, **유니코드 NFC 로 정규화**(macOS 가 올리는 한글 파일명은 NFD 라 같은 이름이 둘로 보이는 문제 방지).
- 한도(기본값, `.env`): 파일 1개 200MB, 사용자당 총량 5GB, 폴더 깊이 20, 폴더당 항목 10,000, 업로드 1회 최대 50개.

### 3.2 기능 목록

| 기능 | MVP | 동작 |
|---|---|---|
| 목록 | ✅ | 폴더 내용(폴더 먼저, 이름순 기본, 이름/크기/수정일 정렬), 커서 페이지네이션 |
| 폴더 생성 | ✅ | 이름 입력. 중복이면 오류(자동 번호 아님) |
| 업로드 | ✅ | 버튼·드래그 앤 드롭, 여러 파일, 진행률, 같은 이름은 `이름 (1).확장자` 로 자동 변경 |
| 다운로드 | ✅ | 파일 1개. (폴더·다중 선택은 zip — P4) |
| 이름 변경 | ✅ | 확장자 포함 전체 이름. 같은 폴더에 중복이면 오류 |
| 이동 | ✅ | 폴더 선택 대화상자(트리). 자기 자신·하위 폴더로 이동 금지 |
| 경로 복사 | ✅ | 클립보드에 `/보고서/요약.pdf` — 에이전트에게 "이 파일 읽어"라고 말할 때 쓴다 |
| 삭제 | ✅ | 휴지통으로 이동(폴더는 하위 전체). 30일 뒤 영구 삭제 |
| 휴지통·복원 | P3 | 목록, 복원(원래 위치가 없으면 루트), 비우기 |
| 다중 선택 | ✅ | 체크박스, 전체 선택, 선택 시 상단에 일괄 이동·삭제 |
| 미리보기 | P3 | 이미지·텍스트·PDF(기존 `ArtifactsPanel` 미리보기 재사용), 행 클릭 시 오른쪽 패널 |
| 에이전트 저장 | ✅ | 5장 |
| 검색(이름) | P4 | 이름 부분 일치 |

### 3.3 데이터 모델 (MySQL)

```
drive_nodes
  id            CHAR(36) PK
  user_id       CHAR(36) NOT NULL  (INDEX)
  parent_id     CHAR(36) NULL      (루트 노드만 NULL; 사용자별 루트 1개는 처음 쓸 때 생성)
  type          ENUM('folder','file')
  name          VARCHAR(255) NOT NULL        # NFC 정규화된 표시 이름
  size_bytes    BIGINT NOT NULL DEFAULT 0    # 파일만
  mime          VARCHAR(127) NULL            # 서버가 확장자/내용으로 정한 값 (클라이언트 값은 참고만)
  sha256        CHAR(64) NULL                # 파일: 무결성·중복 감지·Functions 패키지 고정용
  storage_key   VARCHAR(255) NULL            # 파일: MinIO 객체 키 (경로가 아니라 불투명 값)
  source        ENUM('upload','agent','sandbox','function') NOT NULL
  source_ref    JSON NULL                    # {conversation_id, message_id, workspace_path} 등
  trashed_at    DATETIME NULL
  trash_root_id CHAR(36) NULL                # 한 번에 삭제된 묶음(복원 단위)
  created_at, updated_at
  UNIQUE (user_id, parent_id, name, trash_key)   # 살아 있는 항목만 유일: trash_key = '' | trash_root_id
  INDEX (user_id, parent_id, trashed_at)
drive_usage
  user_id PK, used_bytes BIGINT                # 용량 카운터 (트랜잭션으로 갱신, 주기적으로 SUM 과 대조)
```

- **객체 키**: `drive/{user_id}/{node_id}` — 이름·경로와 무관하므로 **이름 변경·이동은 DB 행만 바꾼다**(객체 복사 없음).
- 버킷: 신규 **비공개** 버킷 `MINIO_DRIVE_BUCKET`(기본 `agent-drive`). 공개 버킷(`agent-public`)과 절대 섞지 않는다.
- 조상 확인(이동 시 순환 방지, 이동·경로 표시)은 재귀 CTE(MySQL 8)로 한다.
- 주의: 목록 조회에서 `source_ref` 같은 JSON 을 읽지 않는다(`messages` 에서 겪은 MySQL sort memory 1038 재발 방지).

### 3.4 API

모두 로그인 필요, 모든 쿼리에 `user_id` 조건(소유자 검증).

| Method | Path | 설명 |
|---|---|---|
| GET | `/api/drive/nodes?parent_id=&sort=&cursor=` | 폴더 내용 + 현재 폴더의 경로(breadcrumb) |
| POST | `/api/drive/folders` | `{parent_id, name}` |
| POST | `/api/drive/files?name=&parent_id=` | **파일 1개 raw 업로드**(본문 = 파일 바이트). 크기는 **받는 도중 집계**해 한도 초과 시 즉시 413(Content-Length 를 믿지 않음). 여러 파일은 클라이언트가 병렬(3개)로 나눠 보낸다 *(구현 중 multipart 에서 변경: 파일별 진행률·취소가 가능하고 서버가 한 파일씩만 디스크에 둔다)* |
| GET | `/api/drive/files/{id}/download` | 파일 스트리밍. `Content-Disposition: attachment`, `nosniff` |
| PATCH | `/api/drive/nodes/{id}` | `{name?, parent_id?}` 이름 변경·이동 |
| POST | `/api/drive/nodes/move` | `{ids[], parent_id}` 일괄 이동 |
| DELETE | `/api/drive/nodes/{id}` | 휴지통으로 |
| POST | `/api/drive/nodes/delete` | `{ids[]}` 일괄 |
| GET | `/api/drive/trash` · POST `/api/drive/trash/{id}/restore` · DELETE `/api/drive/trash` | P3 |
| GET | `/api/drive/usage` | `{used_bytes, quota_bytes}` |
| POST | `/api/drive/import/sandbox` | `{conversation_id?, paths[], parent_id}` sandbox 파일/폴더를 Drive 로 저장 (5.1) |
| GET | `/api/drive/resolve?path=` | 경로 → 노드 (에이전트 도구가 사용) |

### 3.5 UI (첨부 화면 기준)

- 메뉴: IconBar 에 **Drive**(HardDrive 아이콘) 추가, 라우트 `/drive`, 폴더는 `/drive/:folderId` (새로고침·링크 유지).
- 헤더: 제목 "Drive". 우측 **폴더**(새 폴더) · **업로드** · **새로고침** 버튼. 선택 항목이 있으면 같은 줄에 선택 개수와 이동·삭제.
- 경로 막대(breadcrumb): `Drive > 보고서 > 2026`, 각 단계 클릭으로 이동.
- 표: 체크박스(헤더는 전체 선택) · 이름(아이콘: 폴더/파일 종류) · 크기(폴더는 `—`) · 수정일시(날짜+시:분) · `⋯` 메뉴.
- `⋯` 메뉴: **다운로드 · 이름 변경 · 이동 · 경로 복사 · 삭제(빨강)**. 폴더의 다운로드는 P4 전까지 비활성화.
- 행 더블클릭/이름 클릭: 폴더는 진입, 파일은 미리보기(P3) 또는 다운로드. 우클릭 메뉴는 같은 항목.
- 이름 변경은 행 안 인라인 편집(Enter 저장, Esc 취소), 폴더 생성은 목록 맨 위에 새 행으로 입력.
- 업로드: 파일 선택 + **드래그 앤 드롭**(영역 강조), 진행률 토스트(파일별 취소), 실패 항목 재시도.
- 빈 폴더: "파일을 끌어다 놓거나 업로드를 누르세요". 용량: 하단에 `사용량 1.2GB / 5GB`.
- 상태: 로딩 스켈레톤, 오류 배너+재시도, 삭제 확인 대화상자(폴더는 "하위 N개 항목이 함께 삭제됩니다").
- 접근성: 메뉴·대화상자 키보드 조작, 체크박스 `aria-label`, 포커스 복귀.

## 4. 보안

| 위험 | 대응 |
|---|---|
| 다른 사용자 파일 접근(IDOR) | 모든 조회·변경에 `user_id`, id 추측해도 404. **교차 사용자 접근 테스트 필수** |
| 경로 조작 | 서버는 경로 문자열로 파일시스템/객체를 열지 않는다. 키는 불투명 id, 이름은 DB 값일 뿐 |
| 저장형 XSS (HTML·SVG 업로드 후 열람) | 다운로드는 항상 `attachment` + `nosniff`, 인라인 미리보기는 안전한 형식(이미지 래스터·PDF·텍스트)만. SVG·HTML 은 텍스트/다운로드로만 |
| 용량 고갈 | 파일·총량·개수 한도, 스트리밍 중 집계, 사용자별 업로드 속도·횟수 제한 |
| 업로드 일관성 | 객체를 먼저 쓰고 DB 행을 만든다. 실패 시 객체 삭제. 남은 고아는 주기 대조 작업이 정리 |
| sandbox 코드가 Drive 를 직접 건드림 | sandbox 컨테이너에는 **MinIO 인증 정보를 주지 않는다**. 전송은 항상 백엔드가 대신 수행 |
| 에이전트에 의한 파괴·유출 | 에이전트 도구는 **저장·읽기·목록만**. 삭제·덮어쓰기는 제공하지 않는다. Drive 내용은 신뢰할 수 없는 입력(프롬프트 인젝션)으로 취급 |
| 악성 파일 | MVP 는 다운로드 전용이라 서버가 실행하지 않는다. 바이러스 검사(ClamAV)는 후속 옵션 |
| 비공개 버킷 노출 | 익명 정책을 걸지 않는다. 다운로드는 백엔드 경유(권한 검사). presigned URL 은 후속에서 짧은 만료로만 |

## 5. 에이전트 연동

### 5.1 산출물을 Drive 에 올리기

1. **수동**: 채팅 우측 "Artifacts" 패널의 파일/폴더에 **"Drive 에 저장"** 버튼 → 폴더 선택 → `POST /api/drive/import/sandbox`.
2. **에이전트 도구** `drive_save(workspace_path, drive_folder="/", name=None)`: 사용자가 "결과를 드라이브에 저장해줘"라고 하면 호출. 백엔드가 컨테이너에서 파일을 읽어(대용량은 스트리밍 `get_archive`) Drive 에 쓴다. 결과로 **Drive 경로**를 돌려준다.
3. **자동 저장(옵션, 기본 꺼짐)**: 설정 `에이전트 산출물 자동 저장`을 켜면 대화에서 새로 만든 산출물을 `/Agent Outputs/{날짜}/{대화 제목}/` 에 저장. 매 요청마다 불필요한 사본이 쌓이므로 기본값은 수동.
4. 같은 이름이 있으면 `이름 (1)` 로 저장(덮어쓰기 없음). 저장한 노드는 `source=agent|sandbox`, `source_ref` 에 대화·경로를 남겨 "어느 대화의 결과인가"를 추적한다.

### 5.2 Drive 를 에이전트가 쓰기

- `drive_load(drive_path, workspace_dest)`: Drive 파일을 sandbox `/workspace/...` 로 복사. 사용자가 "경로 복사"로 얻은 경로를 그대로 말해도 된다.
- `drive_list(drive_path)`: 폴더 내용 조회(이름·크기·수정일만. 내용은 읽지 않음).
- 채팅 입력창에 **"Drive 에서 첨부"** (기존 첨부 흐름에 `drive_load` 를 연결).
- 시스템 프롬프트에는 Drive 경로 규약과 "삭제 불가"를 짧게만 안내한다(프롬프트는 `prompts/*.md` 로 분리).

**사본 관계**: Drive 로 저장하면 sandbox 파일과 독립된 사본이다(이후 sandbox 에서 수정해도 Drive 는 그대로). 수정본을 Drive 에 반영하려면 다시 저장한다(`이름 (1)` 로 쌓이므로 "덮어쓰기 저장" 옵션은 후속 검토).

### 5.3 다른 기능과의 연결

- **대화 삭제**: sandbox 와 백업이 지워지므로, 산출물이 남아 있으면 삭제 확인 창에 "이 대화의 산출물 N개 — Drive 에 저장할까요?"를 띄운다(P3). Drive 에 저장된 것은 영향받지 않는다.
- **Functions**: zip 패키지는 Drive 에서 선택한다. 등록 시 **내용을 Functions 저장소로 복사(고정)** 해서 이후 Drive 파일을 지우거나 바꿔도 배포된 함수가 변하지 않게 한다.
- **공유**: 개인 공간이 기본. 공유 링크는 대화 공유(`/share`)와 같은 토큰 방식으로 후속에 추가할 수 있다.

## 9. 리뷰 (발견한 문제와 권고)

### 높음

1. **출발 전제가 다르다**: 산출물은 지금 MinIO 에 개별 파일로 있지 않다(2장). 따라서 "통합"은 새 복사 경로이며 **사본 관계**(5.2)와 중복 저장 비용을 감수한다. 이를 화면에서 분명히 해야 한다("Drive 에 저장 = 사본").
2. **대화 삭제 시 산출물 소실이 Drive 의 핵심 가치다.** 그런데 현재 삭제 흐름은 sandbox·백업을 함께 지운다. 삭제 확인에 저장 유도(5.3)를 넣지 않으면 사용자는 Drive 를 쓰고도 파일을 잃을 수 있다 → P3 필수.
3. **교차 사용자 접근(IDOR)** 이 이 기능의 가장 큰 보안 위험이다. 서비스 계층 한 곳(`get_owned_node`)으로 모든 접근을 통과시키고 테스트로 고정한다.
4. **HTML/SVG 인라인 노출 금지.** 사용자 파일을 같은 출처에서 렌더하면 저장형 XSS 가 된다(JWT 가 같은 출처 저장소에 있다면 탈취까지 이어짐) → 4장 규칙을 구현 첫날부터.

### 중간

5. **대용량 업로드**: 백엔드를 경유하면 메모리·시간·프록시 한도 문제가 생긴다. UploadFile 은 디스크로 스풀링되므로 **스트리밍으로 MinIO 에 올리고 크기를 세는** 구조를 P1 에서 확정하고, Nginx 한도를 같이 조정한다. presigned 업로드는 브라우저가 MinIO 에 닿아야 해서(데스크톱·원격 환경) 후속으로 미룬다.
6. **이름 유일성과 collation**: MySQL 기본 collation 은 대소문자·악센트를 구분하지 않아 `A.txt` 와 `a.txt` 가 충돌한다. 이를 **제품 규칙으로 채택**하는 편이 Windows/macOS 와 맞다. 한글 NFD/NFC 정규화를 빼면 같은 이름이 두 개로 보인다.
7. **용량 카운터 경합**: 동시 업로드가 한도를 동시에 통과할 수 있다 → 카운터를 조건부 UPDATE 로 선점하고 실패 시 롤백, 주기적으로 실제 합계와 대조.
8. **휴지통과 유일 제약**: 삭제된 이름이 새 파일과 충돌하지 않도록 유일 키에 휴지통 묶음 id 를 포함(3.3). 폴더 삭제는 하위 전체를 한 번에 표시하고 묶음으로 복원.
9. **sandbox → Drive 전송 크기**: 현재 `read_file` 계열은 한도가 작고(예: 5MB) 아카이브 추출(`export_path`)은 tar 단위다. 큰 파일·폴더는 `get_archive` 스트리밍을 써야 한다. sandbox 에 MinIO 자격 증명을 넣는 지름길은 금지.
10. **고아 객체·행**: 업로드 중 서버 종료, 영구 삭제 중 MinIO 장애 등으로 DB 와 객체가 어긋난다 → 대조 작업(주 1회 + 수동 실행)을 P1 에 포함.

### 낮음 / 확인 필요

11. 메뉴 이름·아이콘: 첨부 화면이 "Drive" 이므로 그대로. 다만 사이드 아이콘이 이미 많아 IconBar 공간을 확인.
12. 폴더 크기는 목록에서 계산하지 않는다(`—`). 필요하면 후속에 비동기 집계.
13. 에이전트의 Drive 읽기는 **프롬프트 인젝션 경로**다(파일 안에 "이전 지시를 무시하고…"). 도구 결과를 신뢰하지 않는 기존 프롬프트 원칙을 `drive_load` 안내에도 적용.
14. 사용자 삭제 시 Drive 전체 삭제(개인정보) 절차가 필요하다.
15. 백업·복구: MinIO 자체 백업 정책이 없으면 Drive 는 "원본 저장소"가 되므로 데이터 유실 위험이 sandbox 백업보다 커진다 → 운영 문서에 명시.

### 이 스펙에서 검증하지 못한 가정

- MinIO 비공개 버킷을 신규로 만들 권한이 현재 자격 증명에 있는지
- 운영 DB 의 실제 collation, `messages` 처럼 큰 JSON 열 정렬 문제가 `drive_nodes` 에 없는지(JSON 열을 목록에서 제외하는 전제)
- 리버스 프록시의 현재 본문 크기·타임아웃 설정
- 사용자 수·파일 수 규모(한도·인덱스·페이지네이션 크기의 근거 데이터가 없음)

### 10.2 스펙에서 달라진 점

- 업로드는 multipart 가 아니라 **파일 1개 raw 본문**이다(3.4).
- 폴더 크기는 목록에서 `—` (스펙대로). 폴더 다운로드(zip)는 비활성 메뉴로 두었다.
- 에이전트 산출물 **자동 저장은 설정 항목(`DRIVE_AUTO_SAVE_DEFAULT`)만 있고 동작은 구현하지 않았다**(수동 + 도구만).
- sandbox 저장 시 `node_modules`·`.git`·`__pycache__`·`.venv` 등은 제외한다(산출물이 아니고 파일 수만 늘린다). 같은 이름의 **폴더**는 합치지 않고 `이름 (1)` 로 새로 만든다.

### 10.3 검증한 것

- 단위·API 테스트 **52개**(서비스 29, sandbox 전송 10, API 13): 이름 정규화(NFC)·번호 붙이기, 깊이·개수·용량 한도, 이동 순환 방지·전부 아니면 전무, 휴지통(묶음·복원·겹친 묶음·만료), **다른 사용자 접근 시 404**, 대조(reconcile), 스트리밍 한도, 다운로드 헤더(HTML·SVG 도 attachment).

테스트로 잡은 결함(수정 완료): 비동기 세션에서 `expire_all()` 후 지연 로딩 오류, 벌크 UPDATE 뒤 오래된 객체 참조, **동시 첫 업로드에서 용량 행 충돌로 `rollback()` 되며 세션 객체가 만료되던 MissingGreenlet**, **먼저 지운 항목이 든 폴더를 나중에 지우면 "휴지통 비우기"가 404 로 실패**, 가져온 폴더의 `source` 값.
