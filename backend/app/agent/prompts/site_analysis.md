진행 방법
1. 위 입력값을 이 사이트의 화면에서 실제로 하나씩 넣어 보세요. 입력값마다 어떤 방식(주소 파라미터, 입력창, 자동완성 목록, 달력, 버튼)으로 들어가는지, 넣은 뒤 주소가 어떻게 바뀌는지 기록합니다. 주소에서 입력값 자리는 `{입력키}` 로 바꿔 적되, `{}` 안에는 위 "입력값 정의"의 key 만 쓰세요. 입력값이 아닌 고정 파라미터(예: `searchType=1`, `fareType=Y`)는 `{}` 없이 실제로 확인한 값을 그대로 적고, 값의 형식(날짜 `YYYYMMDD` 인지 `YYYY-MM-DD` 인지, 코드 값의 의미)을 `how` 에 함께 적습니다.
   **주소는 최소로 줄여 적으세요.** 화면이 붙인 부가 파라미터(쪽 번호, 개수 제한, 카테고리·세션 코드, 추적 값 등)는 빼고, 조건을 실제로 결정하는 파라미터만 남깁니다. 이번 검색어·카테고리에서만 의미 있는 값은 쓰지 마세요. 줄인 주소가 실제로 같은 결과를 내는지 직접 열어 확인해 보고, 확인하지 못했다면 화면에서 얻은 주소 대신 방법을 말로 적으세요(`how`).
2. 표준 단계를 순서대로 수행하면서, 단계마다 이 사이트에서 무엇을 누르고 어디로 이동하는지 기록하세요.
3. **홈 화면부터 보세요.** 검색으로 바로 들어가기 전에 시작 주소의 홈 화면에서 상단 메뉴, 카테고리 메뉴, 이 분야 작업의 진입점(예: 항공권·호텔·시간표 메뉴)을 읽고, 이름·위치·이동 주소를 `menus` 에 기록하세요. `menus` 는 사이트 전체의 메뉴·화면 지도입니다. 한 화면 안의 정렬 옵션이나 탭(예: 상품 상세의 '최저가순')과 검색창은 메뉴가 아니라 `inputs`·`flow` 의 설명으로 적습니다. **이 분야 작업에 쓰는 메뉴만** 남기세요 (검색·카테고리·이 분야로 가는 진입점). 작업과 무관한 서비스 메뉴(커뮤니티, 이벤트, 다른 분야 등)는 적지 않습니다.
4. **읽기만 합니다.** 로그인, 장바구니 담기, 좌석 선택, 예약·결제·주문처럼 상태를 바꾸는 동작은 실행하지 말고, 그 버튼의 이름과 위치, 누르면 이어질 화면의 이름만 기록하세요. 결제 직전 화면까지 가는 길이 보이면 그 이름과 주소를 `stop_point` 로 적습니다.
5. 직접 확인한 것만 적으세요. 화면의 **초기값**(미리 채워진 입력, 이미 선택된 인원·필터, 최근 본 항목)은 이 브라우저에 남은 이전 사용 흔적일 수 있으니 사이트의 기본값으로 적지 말고, 입력값은 매번 직접 설정하세요. **확인하지 못한 항목은 `how`·`url`·`stop_point` 를 빈 문자열로 두고**, 왜 확인하지 못했는지는 분석 메모에만 "미확인: …"으로 적습니다 (`how` 에 "미확인" 문장을 쓰면 다른 에이전트에게 그대로 전달됩니다). **상태를 바꾸는 단계(표준 단계 목록에서 '상태를 바꾸는 단계'로 표시된 것)는 `how` 를 비워 두세요.** "…것으로 보인다" 같은 추측은 어떤 항목에도 쓰지 않습니다.
   **`how` 에는 실제로 성공한 방법만 적으세요.** 시도했지만 화면이 바뀌지 않았거나 실패한 방법(예: 홈 검색창에 입력 후 Enter 를 쳐도 결과 화면으로 가지 않음)은 `how` 에 방법으로 쓰지 말고, 성공한 다른 방법(예: 주소로 바로 이동)을 `how` 에 쓴 뒤 실패한 방법은 `<요령>` 에 "…는 동작하지 않으니 쓰지 말 것"으로 적습니다. 성공/실패를 직접 확인하지 못한 방법은 `how` 에 넣지 않습니다. 현재 저장된 구조가 있으면, 화면과 맞는 것은 유지하고 다른 것은 고치세요.
6. 보안 확인(캡차)이나 로그인 요구가 나오면 우회하지 말고, 어느 화면에서 어떻게 나타났는지 기록한 뒤 거기까지의 결과로 마무리하세요. 단, 도구가 "사용자가 CAPTCHA 를 해결했습니다"라고 알리면 그 화면에서 이어서 분석하세요.
7. **직접 이동이 되는지 구분해서 기록하세요.** 하위 화면의 주소로 바로 이동했는데 핵심 화면(검색 폼·시간표 같은 위젯)이 비어 있고 헤더·배너만 보이면, 그 주소는 직접 이동용 주소가 아닙니다. 홈이나 상위 화면에서 메뉴·버튼을 눌러 들어가 보고, 어느 쪽이 되는지(직접 이동 가능/버튼으로만 진입)를 `entry` 와 `<요령>` 에 적으세요. 직접 이동이 안 되는 주소는 `flow` 의 `url` 에 넣지 마세요. 한 화면에서 같은 동작을 반복하지 마세요. 막히면 막힌 지점을 기록하고 다른 항목으로 넘어가세요.
8. **팝업은 닫고 진행하세요** (지침의 팝업 규칙을 따릅니다). 어떤 팝업이 언제 뜨고 어떻게 닫았는지(예: 첫 방문 시 이벤트 팝업, 닫기 버튼 이름)는 `<요령>` 에 한 줄로 적습니다. 팝업을 분석 대상으로 삼지는 마세요.
