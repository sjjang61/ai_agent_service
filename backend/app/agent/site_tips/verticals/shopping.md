가격비교 사이트에서 상품을 찾아 최저가를 확인하고, 필요하면 장바구니에 담는 데까지가 이 분야의 범위입니다. **결제·주문 확정은 하지 않습니다.**

진행 순서
1. 검색어(상품명·모델명·용량)를 정합니다. 사용자가 규격(용량, 개수, 색상)을 말했으면 결과에서 그 규격이 맞는 상품만 비교합니다.
2. 사이트의 검색 결과 주소로 바로 이동하고, 낮은 가격순으로 정렬합니다.
3. **가격은 배송비를 포함한 총액(상품가 + 배송비)으로 비교하고 안내합니다.** 사용자가 "배송비 제외"를 요청한 경우에만 상품가 기준으로 안내합니다. 화면의 최저가·정렬은 상품가 기준인 경우가 많으므로, 상위 결과 여러 개의 배송비를 직접 확인해 더한 총액으로 순위를 다시 매깁니다. 비교는 **같은 규격·같은 조건(카드·멤버십 할인 제외)** 끼리 하고, 단위당 가격이 필요하면 직접 계산합니다.
4. 사용자가 담아 달라고 했을 때만 상품 페이지에서 옵션을 고르고 장바구니에 담습니다. 담은 뒤 장바구니 화면에서 상품명·옵션·수량·합계를 확인합니다.
5. 구매하기·주문하기·결제하기는 누르지 않고 멈춥니다.

주의
- 배송비는 "무료배송", "조건부 무료(○원 이상)", "착불", 판매처별 금액으로 다양합니다. 조건부 무료는 이번 구매 금액에서 무료가 되는지 판단하고, 판단할 수 없으면 근거와 함께 두 경우를 모두 적으세요.
- 카드 할인가·멤버십 적립가처럼 조건이 붙은 가격은 총액에 섞지 말고 별도로 표기하세요.
- 광고·제휴 영역의 상품과 일반 결과를 구분하세요. 가격이 유독 낮은 항목은 옵션·중고·해외배송인지 확인합니다.
- 품절·재고 없음 표시가 있는 상품은 최저가 후보에서 뺍니다.
- 로그인이 필요해지면 `request_user_login` 을 호출하세요.

보고 항목: 사이트, 상품명(규격), **배송비 포함 총액**(사용자가 배송비 제외를 요청했으면 상품가), 상품가, 배송비, 판매처, 상품 주소, 정렬·필터 적용 여부, 장바구니 담기 결과.

## 분석 체크리스트
- 검색 결과 주소 형식은? (검색어 파라미터, 인코딩)
- 정렬(낮은 가격순)은 주소 파라미터로 되는가, 버튼을 눌러야 하는가? 눌렀을 때 주소는 어떻게 바뀌는가?
- 결과 목록의 한 항목에는 어떤 정보가 있는가? (상품명, 가격, 배송비, 판매처, 광고 표시)
- 가격이 "최저가 기준"인지 "판매처별 가격"인지? 옵션별로 가격이 갈리는가?
- 상품 상세에서 판매처로 이동하는 방식은? (새 탭, 외부 사이트)
- 장바구니 담기: 어느 화면에서 어떤 버튼인가? 로그인이 필요한가? 담긴 뒤 확인할 수 있는 화면은?
- 결제로 넘어가는 버튼의 이름과 화면 주소는? (멈출 지점)
- 로그인·캡차·봇 차단이 있는가? 안내 문구는 무엇인가?
